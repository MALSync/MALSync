# Chibi page implementations

Every folder in `implementations/` adds support for one website. A page is a `PageInterface` (`pageInterface.ts`, read its JSDoc) whose members are functions that build **ChibiScript** with the `$c` builder. At build time each function is called once and compiled to JSON (`dist/webextension/chibi/pages/<Key>.json`). The extension downloads that JSON and interprets it on the website, so broken pages can be fixed without an extension release.

This means **page code never runs in the browser**. Only the `$c` chain it returns does. Variables, `if`, `document.*`, `window.*` or helper logic run once at build time and are frozen. All runtime logic must be expressed with `$c` functions.

## Rules for contributions

- **Only chibi pages are accepted.** `src/pages/` holds legacy implementations: do not add pages there, do not edit them for new features, and do not use them as examples. A site that only exists as a legacy page gets a new chibi implementation.
- No clones or fake websites of an existing site.
- Do not commit `README.md`, `pages.md` or other generated lists. They are autogenerated.
- Do not change `src/chibiScript` for a single page. If a page needs a new chibi function, it needs to be discussed with the maintainers.

## Setup

Requires node >= 22.12 and npm >= 8.

```sh
npm install
npm run build                           # initial build (Windows: npm run build:win), also generates the $c types
npm run build:test                      # browser bundles in test/dist (testCode.js, chibiDev.js)
npm run dev:webextension:content        # keep running: rebuilds dist/webextension/chibi on every change
npm run chibi                           # keep running: the chibi Chrome, see Workflow
```

`npm run build:chibiTypes` regenerates `src/chibiScript/FUNCTIONS.md`, the compact reference of every `$c` function (gitignored). Read it instead of the function sources in `src/chibiScript/functions`.

## Workflow

Develop against the real site in the chibi Chrome. Start it in the background with `npm run chibi -- [url]`. It is a normal visible Chrome with a dev extension that provides `window.ChibiDev` and `$c` on every page, using the current content build. Page changes are picked up when you reload the tab. The process keeps running until the browser is closed.

Control the browser with the Chrome DevTools MCP (`chrome-devtools`, configured in `.mcp.json` to connect to `http://127.0.0.1:9222`). Use `navigate_page` and `take_snapshot` to explore the site, and `evaluate_script` to run ChibiScript in the page:

```js
async () => ChibiDev.exec($c.querySelector('h1').text().trim())     // { value, errors }
async () => ChibiDev.exec($c => $c.url().urlPart(4).run())
async () => ChibiDev.exec($c.url().this('sync.getEpisode'))         // call the page's own functions
async () => ChibiDev.runPage()                                      // run the whole page like the extension
```

- `exec` runs the real `ChibiConsumer`, so what works there works in the extension. Elements are returned as `<tag#id.class "text">`, and `errors` names the chibi function that failed.
- `runPage()` runs the lifecycle and returns every value, all errors and `expected` in `tests.json` format. `ready: false` means the lifecycle never triggered. The values are still evaluated so you can see which selector is missing. Reload the tab before every `runPage()`, because it starts the lifecycle again.
- After editing `main.ts`, wait until `npm run dev:webextension:content` rebuilt, then reload the tab. A new page also has to be registered in `pages.ts` before it shows up.
- Bot checks: `runPage()` and `exec()` return `challenge: "cloudflare" | "turnstile"` when the page shows one, and `ChibiDev.challenge()` checks directly. Some pass by themselves, so wait a few seconds and check again. If it stays, ask the user to solve it in the visible browser, wait for their reply, then reload and continue. Do not try to solve it yourself. The browser profile (`test/dist/chibi-dev/profile`) keeps the clearance cookies, so this is rarely needed twice.
- `ChibiDev.pages()` shows the loaded pages and which match the current url.
- The browser runs uBlock Origin Lite against ads and pop-ups. If a site behaves differently than for users, check whether a blocked request is the cause (`list_network_requests`).

Before finishing, run the real test with `npm run test:headless <tests.json title>`. Prefix it with `CI=true` to stay headless. The first run caches the page in `test/dist/headless`. If a test cannot pass, for example because the site blocks headless browsers, commit it anyway and say so. The maintainers fix tests during review.

For a check in a real browser, a human loads `dist/webextension` unpacked via `chrome://extensions` (Developer mode).

## Writing a page

The smallest working page only needs `sync` and `lifecycle`. `overview`, `list` and the optional members extend it. Start from a similar existing page:
- **Anime SPA**: `implementations/Miruro`. URL change detection with `detectURLChanges`, plus `syncIsReady`/`overviewIsReady` with `waitUntilTrue`.
- **Manga**: `implementations/AsuraScans`. `readerConfig` for reading progress, a `list` for the chapter list, and `$c.this(...)` to reuse functions.
- **Data from site requests or globals**: `implementations/Crunchyroll`. `features.requestProxy`, `getGlobalVariable` and local helper functions that return `$c` chains.

Conventions:
- Every member returns `$c....run()`. Arguments that are functions receive `$c` (`$c => $c.querySelector('a').run()`). Parameters typed `ChibiParam<T>` take either a value or a nested `$c...run()`.
- `sync.getIdentifier` and `overview.getIdentifier` must return the same value for the same series, and it must be stable across episodes. Prefer url parts over titles.
- `sync.getOverviewUrl` and `nextEpUrl` must be absolute. Use `.urlAbsolute()`.
- `sync.getEpisode` returns a number.
- Use `.ifNotReturn()` before reading from optional elements so a missing element does not log errors.
- `overview.uiInjection` places the MAL-Sync box, which is typically `.uiAfter()` on the title.
- `lifecycle.setup` adds `style.less` (`$c.addStyle(require('./style.less?raw').toString())`), and `style.less` starts with `@import './../pages';`.
- Style the MAL-Sync UI to match the site. After the import, override the variables of `implementations/pages.less` (`@boxBackground`, `@boxFontColor`, `@boxHighlightBackground`, `@activeEp`, `@highlightStyle`, ...).
  - If the site defines CSS variables for its colors, use them (`@boxBackground: var(--background-elevated);`, `background: var(--primary-accent) !important;`), so the UI follows theme switches. List them with `evaluate_script`: `() => { const s = getComputedStyle(document.documentElement); return [...s].filter(p => /^--.*(primary|accent|brand|theme|background|bg)/i.test(p)).slice(0, 60).map(p => p + ': ' + s.getPropertyValue(p).trim()); }`
  - Otherwise read the colors from the site's elements, for example `getComputedStyle(document.querySelector('a.btn-primary')).backgroundColor`, and use them as hex values (`@activeEp: #1e73be;`).
- `lifecycle.ready` must eventually call `.trigger()`. SPAs wrap it in `detectURLChanges`. A 404 guard looks like `$c.title().contains('Error 404').ifThen($c => $c.string('404').log().return().run())`.
- `urls.match` uses WebExtension match patterns. `domain` is the main origin.
- New pages are registered in `pages.ts`, next to the other imports.

## tests.json

`tests.json` sits next to `main.ts`. Use `expected` from `runPage()` on each test url, and check the values before committing. Include at least one sync (episode/chapter) url and one overview url, plus edge cases when the site has them.

```json
{ "title": "Name", "url": "https://site", "testCases": [
  { "url": "https://site/watch/123/episode-1", "expected": { "sync": true, "title": "...", "identifier": "123",
    "episode": 1, "overviewUrl": "...", "nextEpUrl": "...", "uiSelector": false } },
  { "url": "https://site/watch/123/", "expected": { "sync": false, "title": "...", "identifier": "123",
    "uiSelector": true, "epList": { "2": "https://site/watch/123/episode-2" } } } ] }
```
